# ChatGPT 与 Codex CLI 检测设计

## 目标

Codex Switcher 分别检测 ChatGPT 和 Codex CLI，根据本机可用的登录入口调整切换与新增账号流程。ChatGPT 保持自动关闭和打开；Codex CLI 不由应用控制，只提醒用户手动退出和重新打开。

## 安装检测

- ChatGPT：沿用当前应用路径与 macOS 应用登记信息检测。
- Codex CLI：先检查当前 `PATH` 和常见安装目录；未找到时，在应用启动时通过登录 Shell 执行一次 `command -v codex`，并缓存结果。

## 四种情况

| ChatGPT | Codex CLI | 切换账号 | 新增账号 |
|---|---|---|---|
| 已安装 | 已安装 | 自动关闭和打开 ChatGPT；切换前提醒退出 CLI，完成后提醒重新打开 CLI | 使用 ChatGPT 登录；开始前提醒退出 CLI，完成或取消后提醒重新打开 CLI |
| 已安装 | 未安装 | 保持现有 ChatGPT 自动处理 | 保持现有 ChatGPT 登录流程，不显示 CLI 提示 |
| 未安装 | 已安装 | 正常切换；切换前提醒退出 CLI，完成后提醒重新打开 CLI | 备份当前账号后等待用户在终端执行 `codex login`；完成或取消后提醒重新打开 CLI |
| 未安装 | 未安装 | 正常切换，不执行应用关闭或打开 | 在改动任何账号文件前停止，并说明需要 ChatGPT 或 Codex CLI 作为登录入口 |

## 切换账号

确认框根据检测结果组合提示：ChatGPT 已安装时说明会自动关闭并重新打开；Codex CLI 已安装时增加“请先退出 CLI，完成后重新打开”的提醒。账号文件切换本身不依赖两者，因此四种情况下都允许执行。

切换成功后：

- ChatGPT 已安装时自动重新打开。
- Codex CLI 已安装时显示重新打开 CLI 的提示。
- ChatGPT 未安装不再作为错误。

## 新增账号

至少存在一个登录入口时才开始备份账号文件。

- 有 ChatGPT：自动关闭并打开 ChatGPT，等待新凭据。
- 只有 Codex CLI：显示 `codex login` 操作提示，等待用户手动登录产生新凭据。
- 两者都没有：直接停止，不创建待处理记录，不移动 `auth.json`。

现有新增账号事务继续负责取消恢复和意外退出恢复。Codex CLI 登录与 ChatGPT 登录共用同一套新凭据检测和账号登记逻辑。

## 提示与错误

- 检测到 Codex CLI 时才显示 CLI 提示。
- CLI 提示属于正常操作说明，不显示成错误。
- 用户取消新增账号后恢复旧凭据；如果之前提示退出 CLI，则提醒重新打开。
- 登录入口启动失败时保留当前的恢复机制，不能覆盖成功生成的新凭据。

## 验证

- 对安装状态组合和提示文案选择做独立检查。
- 验证只有 CLI 时可以进入新增流程，并能完成或取消。
- 验证两者都没有时，`auth.json`、账号备份和待处理记录均不变化。
- 验证切换账号在四种情况下都能执行。
- 运行核心检查、GitHub macOS 构建和 DMG 打包。
